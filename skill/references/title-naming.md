# 标题命名方法

本文件用于长文的标题提炼、候选生成、筛选与复核。标题不是正文摘要，而是对读者的阅读承诺；承诺必须能被正文兑现。

## 1. 先提炼五个命名输入

写标题前，先从已核验素材和选题中提取：

| 输入 | 要回答的问题 |
| --- | --- |
| 内容对象 | 这篇文章具体写什么人、产品、问题或案例？ |
| 目标读者 | 谁最需要打开它？ |
| 核心收益 | 读者读完能得到什么判断、方法或结果？ |
| 主要张力 | 痛点、冲突、反常识、选择困难或机会窗口是什么？ |
| 证据边界 | 哪些数字、案例、结论和时效信息可以真实支撑？ |

如果这五项无法说清，先补素材或缩小选题，不靠更夸张的措辞掩盖内容空泛。

## 2. 工作标题与最终标题分离

- **工作标题**：在调研和骨架阶段使用，优先写清“对象 + 读者 + 结果/问题 + 方法”，允许朴素、偏长。
- **最终标题**：在骨架或初稿确认文章真正的核心承诺后再定。若正文最强证据与工作标题不一致，提出改名建议并等待用户确认，不静默替换。
- 用户已经给出标题时，先评估并保留为工作标题；只有存在明显的歧义、失真或承诺无法兑现时，才提出替代方案。

## 3. 候选标题机制

默认生成 3-4 个方向，必须是不同的点击理由，不是同一句话换同义词：

1. **结果承诺型**：明确读者能获得的结果，以及条件或路径。
2. **问题诊断型**：指出反复出现的痛点，并暗示更深层原因。
3. **对比/冲突型**：呈现表象与本质、旧做法与新做法、选择 A 与 B 的张力。
4. **案例/证据型**：从真实案例、样本、测试或数据进入，再指向可复用结论。
5. **判断/选择型**：帮助读者在工具、方案或行动之间做决定。
6. **清单/工具箱型**：只有在正文确实有对应数量和清单结构时使用数字。

按文章类型优先匹配：教程用结果承诺或清单，评测用证据或判断，深度解析用诊断或对比，经验分享用案例或结果。一个标题可以组合机制，但必须保留一个主点击理由。

## 4. 标题写法约束

- 尽量包含具体名词、场景、对象、数字、时间、限制条件或可见代价；抽象词不能单独承担标题信息。
- 留出一个**有用的悬念**：读者知道文章谈什么，也知道还有一个值得打开的问题；不能故意写成谁都适用的谜语。
- 标题的关键词顺序优先为“对象 → 变化/问题 → 读者收益或判断”；删掉不增加信息的形容词。
- 主标题和副标题有分工：主标题负责对象与张力，副标题负责范围、方法或证据；不得重复表达。
- `？` 只用于文章确实回答的问题；`刚刚`、`最新`、`官宣`等时效词必须有真实时间依据。
- 禁用无证据的“最全、终极、颠覆、必看、彻底、100%”等绝对化承诺，也不使用“震惊”之类空洞刺激词。

## 5. 候选输出与评分

每个候选都记录：标题、主机制、目标读者、阅读收益、需要的证据、潜在误导风险。内部按 1-5 分评估：

| 维度 | 判断标准 |
| --- | --- |
| 清晰度 | 一眼知道对象和内容范围 |
| 点击理由 | 有明确收益、痛点、冲突、好奇或决策价值 |
| 具体性 | 有具体对象、场景、数字、样本、限制或结果 |
| 悬念质量 | 留下一个值得回答但不故弄玄虚的问题 |
| 可信度 | 正文和证据能够兑现标题承诺 |

总分 25 分。平分时优先选择读者收益最清楚、跨平台可复用、夸张风险最低的标题。若候选分高但证据不足，可信度直接判低，并不得推荐。

## 6. 最终发布门禁

发布前检查：

- 标题承诺能在正文前两章内得到回应，全文结论不偏离标题。
- 标题没有把普通观察包装成重大事件，没有把局部测试写成普遍结论。
- 标题中的数字、版本、人物、机构、时间和因果关系均有来源或真实素材支撑。
- 标题与正文结构一致；若改过标题，重新检查开头、章节和结尾是否仍然服务同一承诺。
- 用户明确确认最终标题后，才把它写入正式文章的 `#` 标题。
