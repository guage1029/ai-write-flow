# reader-payoff.md — 读者兑现门禁

> Step 3（选题）、Step 4（骨架）、Step 5（第一遍内容审校）加载。
> 与 `fact-policy.md` 的分工：fact-policy 管「写出来的数字对不对」，本文件管「读者能不能拿到你承诺的东西」。
> 自动化部分由 `scripts/check_article.py` 的 `R*` 检查项覆盖；本文件负责脚本测不出的人工判断。

## 为什么要单独设这道门禁

历史失败样本（一篇 57 行公众号稿）暴露的问题，**没有一项是 AI 腔或事实错误**，全部是读者侧失败：

| 症状 | 事实层面的真相 | 读者体验 |
|------|--------------|---------|
| 标题写「接进 OA 审批流」，正文只讲一个案例 | 每个数字都真实 | 承诺过量，点进来发现被骗 |
| 全文没解释核心对象是什么 | 术语使用正确 | 陌生读者读不懂，读完仍不知道 Jev 是什么 |
| 手里有 12 例完整统计，正文 0 个数字 | 数字都准确 | 最硬的证据被藏起来了 |
| 结论依赖作者自设的 0.2–0.8 区间 | 披露了「教学阈值」 | 披露埋在正文深处，读者看不到地基是自设的 |
| 5 张手绘 SVG，0 张真实界面，0 段代码 | 配图都合规 | 声称是「接入实验」，看不到任何接入产物 |

结论：**事实正确 ≠ 文章成立**。原 skill 的所有门禁都在向下看（文本→事实），缺一层向上看（读者→文本）。

## R1 冷启动：核心对象可被复述

**规则：** 陌生读者读完**开头 300 字**（不是第一段），应该能回答三个问题：

1. 这篇文章讲的是什么**东西**（产品 / 模型 / 方法 / 协议，不是一个笼统的领域）
2. 这个东西和同类东西**有什么不同**
3. 作者**亲手做了什么**，读者能拿到什么

**判定：** 把 H1 标题里的核心术语列出来，逐个在正文前 25% 出现。术语缺任一项 → 补一句定义，不要指望读者点进外链。

**允许的写法：** 直接下定义、给一个具体差异、给一句「它不做什么」。

**禁止的写法：** 用「大家都知道」「作为一款 XX 工具」跳过定义；把定义推到文末的扩展阅读；用一整段行业背景代替对象定义。

**不适用：** 纯观点文章、纯教程文章（教程的对象是读者已有的东西）。这类在 Step 3 标注豁免理由。

## R2 标题兑现：承诺量级必须对等

**规则：** 标题拆出的每个承诺，都要在正文找到**同量级**的落点。

**承诺—落点映射表**（Step 4 骨架阶段必须产出，Step 5 复核）：

| 标题承诺 | 落点要求 |
|---------|---------|
| 一个数字 | 数字必须在正文出现，且口径与标题一致 |
| 一个范围 / 全面 / 全部 | 正文必须给出对应规模的证据（几例、几类、几天） |
| 「接入 / 实现 / 跑通 / 落地 X」 | 正文必须有可验证的接入产物：请求体、代码、界面、运行记录 |
| 「为什么 / 怎么」 | 正文必须回答这个问题，而不是只描述现象 |
| 强断言（「再也不用」「彻底解决」）| 禁止，见 fact-policy.md |

**量级失配的典型形态：**

- 标题说「接进 X 流程」，正文只有一个案例 → 改标题为案例级，或补上全景规模
- 标题说「12 张单子跑下来」，正文 3 张 → 数字必须兑现
- 标题说「对比 A 和 B」，正文只有 A → 补 B，或删掉对比承诺

**阻断条件：** 映射表存在空项 → 骨架不得进入正文填充。

## R3 证据使用义务：手里最强的证据必须进正文

**规则：** 写作前先做**证据盘点**（素材目录、运行日志、benchmark 报告、telemetry、成本记录里都有什么），然后强制回答：

> **如果读者只读这一篇文章，他拿到的最硬的一个证据是什么？这个证据在正文里吗？**

**藏证据的典型形态：**

| 形态 | 症状 | 处理 |
|------|------|------|
| 结论在正文，数字在附录 | 正文全是叙述，`runs/*.json` 里有完整统计 | 把最能改变判断的一到三个数字提到正文 |
| 实验台远大于文章 | demo 有完整界面，文章只有示意图 | 至少补 1 张真实产物图 + 1 段真实请求/输出 |
| 主动声明边界却不给量级 | 写「样本少，不可外推」，但没说多少 | 补样本量、指标、口径 |
| 配图全是示意图 | 全是 SVG 概念图，0 实拍 | 技术/实验类文章必须有真实产物证据 |

**产物证据最低配置（技术实测 / 接入 / 评测类文章）：** 满足以下**至少两项**——

1. 真实代码块（可运行或接近可运行，含关键字段）
2. 真实界面 / 终端 / 实物截图（`.png/.jpg`，非 SVG 示意图）
3. 真实数据表（口径、样本量、指标定义齐全）
4. 真实请求体 / 原始返回 / 日志片段

只有手绘示意图的实测文章，判定为 R3 不通过。

## R4 自证参数：结论依赖自己设定的参数时必须显式声明

**规则：** 当结论依赖下列任一**由作者自己设定、未被外部数据校准**的参数时，必须在**结论出现之前或紧邻位置**声明，不能只在小结或免责段里提一句：

- 阈值 / 区间 / 上下限（分数区间、置信度门槛、金额上限）
- 量表 / 评分标准（尤其是多维度揉进一把尺的量表）
- 基线 / 对照组（自己写的规则基线、自己构造的对照样本）
- 样本标签（自己打的正确 / 错误标注）
- 演示制度 / 虚构规则

**必须写出的三件事：**

1. **这个参数是谁定的** —— 「这个 0.2–0.8 是我为了让流程跑通自己设的」
2. **它决定了什么** —— 「所以『转人工』这个结果不是模型告诉我的，是这个区间告诉我的」
3. **去掉它之后还剩什么结论** —— 「剩下的只有『一次申请可以同时有高业务分和未澄清的私人用途』，这句不需要任何阈值」

**为什么这条是硬门禁：** 阈值自证的实验，很容易被读者读成「模型做出了正确判断」，而实际是「结论被参数定义」。披露位置比披露本身更重要——放在结尾免责段等于没披露。

**推荐处理：** 与其弱化，不如**把它变成全文最锋利的一刀**。把「结论是我提前写好的」摆出来，文章从「我做了个演示」升级成「我告诉你这套东西现在还不能上线」。后者才是程序员和业务方都愿意读、也愿意转发的结论。

## R5 结尾不得与开篇同义重复

**规则：** 结尾必须提供**开篇没有的新东西**，满足其一：

- 下一步的具体动作（含「该做什么」和「先不做什么」）
- 一个读者可以直接拿去用的判断标准
- 一个反直觉的、只有跑完才有资格说的发现

**不构成新东西：** 把开篇或章节小结的句子换个说法再写一遍；「这说明我们还需要继续探索」；预告下一篇但不给本篇结论。

**检测：** 结尾段落与开篇 / H1 / 各级小标题做字面重合度比对，重合过高 → 判为同义重复。

## 各 Step 的执行方式

| Step | 加载 | 做什么 |
|------|------|--------|
| Step 3 选题 | 本文件 | 生成选题时先过 R2 的「承诺—落点」预判；选题方向表新增「读者冷启动一句话」和「产物证据计划」两行 |
| Step 4 骨架 | 本文件 | 第一阶段必须输出【读者兑现映射表】（R2）和【证据账单】（R3）；不通过不进入正文 |
| Step 5 审校 | 本文件 | 第一遍内容审校前 5 项固定为 R1–R5，逐项判定并写入审校报告 |
| Step 6 落盘 | `scripts/check_article.py` | `R*` 检查项非零退出时必须修订 |

## 豁免

以下情况可标注豁免，需在审校报告写明理由：

- **纯观点 / 立场文**：无实验产物，R3 豁免；R1 改为「核心论点可被复述」
- **教程类**：R2 的「接入产物」改为「可复现步骤」；R3 的代码块要求不变
- **续写 / 系列文**：R1 允许引用系列前文，但**核心对象仍需一句定义**（新读者从任意一篇进入）
- **用户明确要求压缩篇幅**：R3 可降为一项，但必须在文中显式说明「完整数据在 X」，不能静默省略
