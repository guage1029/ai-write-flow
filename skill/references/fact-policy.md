# fact-policy.md — 全局事实核验输出门禁

> 所有输出模式（longform_article / card_post）共同遵守的事实准确性底线。
> 这是**输出门禁**，不是调研过程规范——调研过程由 research-config.md 负责。

---

## 适用范围

本策略约束所有进入最终输出的事实表述，无论输出形态是：

- 公众号长文（longform_article）
- 图卡文案（card_post）
- 审校修订后的文章

---

## 高风险字段清单

以下字段必须有 Tier 1/2 官方来源支撑，才能进入任何输出：

| 字段类型 | 示例 |
|---------|------|
| 版本号 | v0.16.0、3.5 Sonnet、GPT-4o |
| 发布时间 / 日期 | 2025 年 6 月发布、昨日上线 |
| 性能数据 | 速度提升 3 倍、延迟降低 40% |
| 模型名称 | Claude 3.5 Sonnet、Gemini 1.5 Pro |
| 支持平台 / 系统 | 支持 macOS / Windows / Linux |
| 安装命令 / API 地址 | pip install hermes-agent==0.16.0 |
| 价格 / 限制 | 免费版每月 100 次、$20/月 |
| 官方集成 / 合作 | 官方支持 MCP 协议 |
| 功能名称归属 | 该功能属于 X 产品，不是 Y 产品 |
| 架构变化 | 从单体改为微服务、新增流式输出 |

## 输出门禁规则

### 禁止写入输出的事实状态

| claim 状态 | 处理方式 |
|-----------|---------|
| `supported`（官方来源核验） | 可写入输出 |
| `unverified`（找不到官方来源） | 禁止写入输出；必须删除或弱化表达 |
| `contradicted`（与官方来源矛盾） | 禁止写入输出；必须阻断并等待用户确认 |
| stale（来源超过 30 天）| 禁止写入发布内容；背景介绍须显式标注 "来源日期" |

### 弱化表达规范

当找不到官方来源，但信息对叙事有价值时，允许弱化表达：

| 禁止写法 | 弱化写法 |
|---------|---------|
| 速度提升了 180 倍 | 官方暂未提供量化数据 |
| 支持所有主流平台 | 已知支持 macOS，其他平台待官方确认 |
| 完全免费 | 当前文档未说明定价，建议以官网为准 |

## 禁止表述

无论哪种输出模式，以下绝对表述都被禁止：

- ❌ 「100% 准确」→ 改为「当前已由官方来源核验」
- ❌ 「史诗级」、「全网最强」、「首个」（无法核验时）
- ❌ 「唯一」、「完全免费」、「无限」（无官方明确说明时）
- ❌ 「专家认为」、「据统计」等模糊归因（须换成具体来源）

## 自设参数披露门禁（R4）

> 与 `reader-payoff.md` § R4 配套。规则：**结论依赖作者自设参数时，免责必须紧邻结论。**

### 属于「自设参数」的东西

| 类型 | 示例 |
|------|------|
| 阈值 / 区间 | 「Noul 在 0.2–0.8 送人工复核」 |
| 量表 / 评分标准 | 「0–3 级评分，0 级写『没有业务理由或明确私人消费』」 |
| 基线 / 对照组 | 「我自己写的规则基线」「我构造的 12 个案例」 |
| 标签 | 「符合我预设的答案」 |
| 演示制度 | 虚构的金额上限、假期规则、审批权限 |

### 强制披露三要素

缺任一要素，判定为披露不足：

1. **谁定的** —「这个区间是我为了让流程跑通自己设的」
2. **它决定了什么** —「所以『转人工』这个结果不是模型告诉我的，是这个区间告诉我的」
3. **去掉它还剩什么结论** —「剩下的只有 X，这句不需要任何阈值」

### 禁止写法

- ❌ 结论在前，免责放在文末「局限」段
- ❌ 「阈值是教学用的」这种不带后果的免责（读者不会知道它决定了结论）
- ❌ 用「仅供参考」替代「谁定的 + 决定了什么」

### 推荐写法

把自证变成全文最锋利的一刀，而不是风险提示。读者愿意读、也愿意转发的结论是「我告诉你这套东西现在还不能上线」，不是「我做了个演示」。

## 证据使用义务（R3）

> 与 `reader-payoff.md` § R3 配套。规则：**用对还不够，还得用上。**

本策略原本只管「写出来的数字有没有来源」。但真实的失败模式是反过来的——数字全部有来源，却一个都没进正文。

### 写作前必做：证据盘点

列出素材里所有可用证据（日志、benchmark 报告、telemetry、成本记录、截图、demo 界面），然后回答：

> **读者只读这一篇，能拿到的最硬的一个证据是什么？它在正文里吗？**

### 藏证据的四种形态

| 形态 | 症状 | 处理 |
|------|------|------|
| 结论在正文，数字在附录 | 正文全是叙述，完整统计在另一个文件 | 提到正文最能改变判断的 1–3 个数字 |
| 实验台远大于文章 | demo 有完整界面，文章只有手绘示意图 | 至少补 1 张真实产物 + 1 段真实请求/返回 |
| 有边界声明无量级 | 写「样本少，不可外推」，但没说多少 | 补样本量、指标定义、计时范围 |
| 对比数字被弱化 | 规则基线低分出现但不解释它衡量什么 | 写清「它衡量的是什么」，避免被读成能力评分 |

### 产物证据最低配置

实测 / 接入 / 评测类文章必须含以下**至少两项**：

- 真实代码块（含关键字段、可运行或接近可运行）
- 真实界面 / 终端 / 实物截图（`.png/.jpg`，非 SVG 示意图）
- 真实数据表（口径、样本量、指标定义齐全）
- 真实请求体 / 原始返回 / 日志片段

### 对外数字的风险闸

小样本高准确率（如 12/12）必须紧邻标注：样本量、标签由谁写、有没有看过结果后改题。规则基线低分必须说明它衡量的是什么。

## 来源质量要求

**高风险字段必须由 Tier 1 或 Tier 2a 来源支撑**（见 `research-config.md` Layer 2）：

| Tier | 来源描述 | 可支撑高风险字段 |
|------|---------|---------------|
| 1 | 官方网站、release notes、官方文档、GitHub releases | ✅ 是 |
| 2a | 官方维护者声明（创始人/核心维护者以官方身份发布的博客/演讲/声明）| ✅ 是 |
| 2b | 第三方分析（非官方博客、媒体分析、社区转述）| ❌ 仅找线索 |
| 3/4 | 科技媒体、社区帖子、论坛 | ❌ 仅找线索 |

优先来源顺序（越靠前越可信）：

1. 官方网站 / 官方公告
2. 官方 GitHub Release / Changelog / Issues
3. 官方文档（docs.xx.com 等）
4. PyPI / npm / package registry 官方元数据
5. 官方社交账号或公开声明
6. 官方维护者在官方身份下的声明（Tier 2a）

禁止将以下来源作为高风险字段的**唯一支撑**：

- 非官方技术博客（即使博主很有名）
- 社区转述（Reddit、V2EX、知乎）
- 未注明作者的转载文章
- 截图（截图可作为候选事实起点，须经外部来源核验后才能进入输出）

## 与其他规范的分工

| 规范文件 | 职责 |
|---------|------|
| `research-config.md` | 调研过程：如何搜集、分层、核查 claim，输出 JSON |

| `card-post-config.md` | 图卡专项：字数限制、卡片数量、输出格式 |
| `checklist.md` | 审校执行清单：逐遍检查项 |
| `scripts/check_article.py` | 自动化：`R1`–`R5` 门禁 + 结构与文风检查 |
