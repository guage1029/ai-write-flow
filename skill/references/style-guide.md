# style-guide.md — 写作风格规范

> 本文件管清晰、可信和可读，不把文章锁进统一模板。作者画像与用户本次要求优先；事实准确性始终优先于口语和传播效果。

## 作者声音

- 从真实触发点开篇：最近看到什么、遇到什么问题、自己做了什么、读者接下来会看到什么。缺少真实经历时，不补造时间、情绪或个人体验。
- 让作者在场：用“我试了 / 我看了日志 / 我发现”等表达交代观察来源和个人判断，不要求每段都出现第一人称。
- 用场景推进论述。案例之间可以按难度、风险或决策变化递进，并用自然过渡说明为什么进入下一例。
- 先写可见动作、输入和结果，再解释技术含义。术语保留准确，第一次出现时用一句白话解释读者真正需要懂的部分。
- 案例后可以加简短的个人小结，说明这次经验能支持什么判断；不为每节硬造金句。
- 如符合文章和发布场景，可保留作者自我介绍、读者定位、关注邀请或下期预告；不自动套入固定口播。

## 结构与节奏

- 先选能承载材料的叙事顺序，再决定标题层级。不要为了满足固定模板，把每段都切成小节。
- `#` 用于整篇标题；`##` 划分主要内容段；`###` 仅在确实有助于定位和扫读时使用；`####` 默认少用。层级连续、语义清楚即可；若使用 `####`，标题开头按同一父级下的顺序使用 `①`、`②`、`③`、`④`……。
- 开篇可以先放作者、背景、核心问题、关键示意图或结果摘要，按读者理解顺序安排，不强制先目录或先表格。
- 步骤用有序列表；多项数据确实需要横向比较时用表格。表格不是所有评测文章的必备项。
- 结尾回到正文证据，给出作者判断、适用范围或读者下一步。标题可用“写在最后”，也可按内容命名；不强制固定结尾标题或上手清单。
- 有配图时按语义段落安排，不为满足配图单位而增删正文标题。

## 段落、句子与强调

- 以手机端好读为目标。短段落是常用节奏，但句长、段长随内容变化；不按固定字数切句。
- 一段尽量围绕一个主要意思。操作步骤、解释和个人判断可以各自成段，长段只在推理连续时保留。
- 加粗只标出关键判断、术语或读者需要扫到的信息，不要求每段加粗，也不为格式凑重点。
- 口语要像作者自然说话，不靠堆语气词、网络词、感叹号或夸张形容词制造“人味”。
- 可用“说实话”“小结一下”等作者常用表达，但只在语境自然时使用，不作为模板填充。

## 证据与表达边界

- 区分日志事实、实测结果、个人推断和一般结论，并写清测试范围。
- 没有同题基线，不比较快慢、准确率或优劣；日志未记录到的结局，不写成已通关或已成功。
- “请求成功 / 返回合法选项 / 完成任务 / 结果更好”是不同层级的结论，不得互相替代。
- 不把口语化当成弱化证据要求的理由。未经验证的结论应缩小范围、加限定或列为待核实。
- 删除空洞套话、机械转场、夸张宣传和无来源归因；保留必要的重复、停顿和自然转折。

## 文章类型参考

以下是可选组织方式，不是必须照抄的模板：

- 实测 / 案例：为什么做 → 自己怎么试 → 由简单案例逐渐增加难度或代价 → 日志说明了什么 → 作者能下什么结论。
- 原理解析：一个具体问题 → 关键机制 → 例子或图示 → 能做与不能做的边界。
- 教程：目标与前置条件 → 操作步骤 → 预期结果 → 常见错误与处理。
- 经验分享：遇到的问题 → 试过的办法 → 结果与代价 → 给读者的建议。

结构应跟着素材走。若案例本身已经形成故事线，优先保留故事线；用承接句解释案例为什么升级或转场，不要再叠一套重复的“背景—原理—总结”。

## 避免的表达

- 助手式开场白、万能总结、空泛的意义拔高和无证据的绝对化结论。
- 为制造悬念而虚构冲突、时间、对话、情绪或人物反应。
- 连续套用“首先、其次、最后”、整齐三段式、每节金句或固定三条结论。
- 把简单事实扩写成教程腔、评测报告腔或产品宣传文案。
- 将作者自然口语统一改写成书面语；也不反向把整篇硬改成网络口吻。
