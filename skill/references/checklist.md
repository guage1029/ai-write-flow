# checklist.md — 多轮审校清单

> Step 5 执行时加载。内容、作者手迹、AI 味、细节、二次扫描按顺序执行，不可跳过。
> 第一遍前 5 项固定为 `reader-payoff.md` § R1-R5，逐项判定并写入审校报告，不得跳过。

---

## 结构审校（随审校流程同步执行）

- [ ] 完整文章有清楚且唯一的主标题
- [ ] 标题层级符合 Markdown 语义；`####` 小标题按同一父级使用连续的 `①`、`②`、`③`、`④`……编号
- [ ] 章节顺序能带读者从问题走到案例、解释和结论
- [ ] 小标题密度适当，没有把每个自然段都拆成编号项
- [ ] 主要观点没有在开篇、章节小结和结尾反复重说
- [ ] 结尾方式符合文章目的；不强制使用“写在最后”或固定清单
- [ ] **实验体量与文章体量匹配**：标题说「接进 / 跑通 / 实测 X」时，正文的案例数、场景数、运行次数与标题承诺同量级（详见 R2）
- [ ] **没有把 demo 当成实验**：实验台规模远大于正文时，要么补全景，要么把标题降到案例级

## 第一遍：内容审校

### 前置：读者兑现门禁（R1-R5，来自 reader-payoff.md，不可跳过）

- [ ] **R1 冷启动** — 陌生读者读完开头 300 字能说出：文章讲的是什么东西、它和同类有何不同、作者亲手做了什么。核心术语在开篇有定义句，不是靠外链
- [ ] **R2 标题兑现** — 已产出【承诺—落点映射表】，无空项；标题里的每个数字都在正文出现；标题动词（接入/实测/对比/全部/复现）在正文有对应证据
- [ ] **R3 证据使用义务** — 已做证据盘点并确认「手里最硬的证据在正文里」。实测/接入类文章至少含两项真实产物：代码块、真实截图（非 SVG）、带口径的数据表、真实请求体或日志
- [ ] **R4 自证参数披露** — 结论若依赖自设阈值、量表、基线、标签或演示制度，免责必须紧邻结论，写清「谁定的 / 它决定了什么 / 去掉它还剩什么结论」，不是放在文末免责段
- [ ] **R5 结尾新信息** — 结尾提供开篇没有的东西：下一步具体动作、读者可用的判断标准、或跑完才有资格说的发现。没有同义重复

### 常规内容项

- [ ] 标题明确写出内容对象、读者收益或核心问题，未只使用抽象口号
- [ ] 标题承诺能被正文和证据兑现，未把局部案例写成普遍结论
- [ ] 标题中的数字、版本、人物、机构、时间和因果关系均有来源或真实素材支撑
- [ ] 标题与正文前两章的回应、全文结论和文章结构一致
- [ ] 主标题与副标题分工不同，没有重复堆叠信息
- [ ] 未使用无证据的“最全、终极、颠覆、必看、彻底、100%”等绝对化承诺
- [ ] 时效词（如“刚刚”“最新”“官宣”）有真实时间依据
- [ ] 最终标题已获得用户确认；未确认时仍标记为工作标题
- [ ] 技术信息准确：版本号正确，术语拼写正确，API 调用准确
- [ ] 性能数据来自真实测试，并交代与该指标相关的环境、模型/API 版本、样本量和计时范围；只有本地性能受硬件影响时才必须列硬件
- [ ] 对比数据前后一致（表格数字 = 正文数字，百分比计算正确）
- [ ] 观点前后无矛盾，段落逻辑连贯，结论有事实支撑
- [ ] 代码块语法正确、可运行，包含必要的 import 和配置
- [ ] 所有案例来自真实经历，没有编造的项目数据
- [ ] 可核验的事实结论能追溯到来源或记录；作者推断清楚标为判断并限定范围
- [ ] 开篇尽早交代真实触发点、作者做了什么或读者能看到什么；不为制造钩子编造冲突
- [ ] 结尾方式符合文章目标；需要来源支撑的技术事实有可追溯出处
- [ ] **对外数字的风险已评估**：高准确率、小样本、强对比数字在正文出现时，紧邻给出样本量、口径和外推限制。规则基线类低分数字须说明它衡量的是什么（例如「规则不处理自然语言」而非「规则只有一半对」）

## 第二遍：作者手迹保护

- [ ] 已判断审校对象是“已有文章”还是“新生成文章”
- [ ] 已有文章只改真正影响理解、节奏或事实准确性的地方
- [ ] 未默认删除作者的语气词、重复、口语停顿和自我修正
- [ ] 未把作者的平直陈述改成对仗、金句或文案腔
- [ ] 未擅自添加时间、地点、情绪、数据、例子
- [ ] 关键改动已说明原因；拿不准的改动标注“可还原”

## 第三遍：AI 味检测/降噪

### P0 必删项

- [ ] 无聊天残留
  - ❌ '当然可以，很高兴为您解答…'
  - ❌ '希望这对你有帮助'
  - ✅ 直接进入正文

- [ ] 无 AI 腔开场白
  - ❌ '当然可以，很高兴为您解答…'
  - ✅ 话不多说，进入正题

- [ ] 无空洞套话
  - ❌ '在当今 AI 技术飞速发展的时代…'
  - ✅ 'AI 工具发展很快，但这个问题还没解决…'

- [ ] 无机械连接词
  - ❌ '首先…其次…最后…综上所述…'
  - ✅ 直接陈述，逻辑顺序自然体现

- [ ] 无模糊归因
  - ❌ '专家认为…研究表明…据统计…'
  - ✅ '[具体机构/作者名] 在 [文章/报告] 中指出…'

- [ ] 无夸张美学
  - ❌ '这是一次革命性的里程碑式突破'
  - ✅ '这让开发效率提升了 40%'

### P1 高频句式

- [ ] 无高频“不是 X，而是 Y / 与其说 X，不如说 Y”假深刻结构
- [ ] 无普通事实后的意义拔高
  - ❌ '这标志着开发范式被重新定义'
  - ✅ 说明具体变化和证据
- [ ] 无连续排比三连
  - ❌ '更快、更稳、更智能'
  - ✅ 只保留真实差异，必要时展开
- [ ] 无连续短句轰炸
  - ❌ '没有犹豫。没有退路。只有向前。'
  - ✅ 合并成自然句

### P2 密度信号

- [ ] '显著提升' → 具体数字
- [ ] '充分利用' → '用好'
- [ ] '进行操作' → 直接动词
- [ ] '实现功能' → 具体功能名
- [ ] '有助于' → '能'
- [ ] '使得' → '让'
- [ ] 空洞好词密度不过高：高效、强大、完善、优秀、稳定
- [ ] 软文词密度不过高：赋能、打造、沉淀、闭环、生态、抓手

### 格式与扫读

- [ ] 标点风格前后一致，无明显混用
- [ ] 破折号 `——` / em dash `—` 每篇最多 1 处，且必须有必要性
- [ ] 无 emoji 装饰标题和正文
- [ ] 无机械加粗；加粗只服务扫读，不制造格式噪音

- [ ] 只有在确有可比数据时才使用 Before/After 表格
- [ ] 加粗用于突出少量关键判断或术语，没有机械地每段加粗

- [ ] 四字词连续堆砌已拆解
  - ❌ '功能强大、性能卓越、操作简便'
  - ✅ '点两下就能用，跑起来比之前快 3 倍'

### 人味增强

- [ ] 第一人称用于说明真实经历、观察来源和个人判断，不要求每段出现
- [ ] 具体时间与个人经历均来自用户材料或可核实记录
- [ ] 对读者理解结论确有必要的技术术语得到解释；不套固定括号格式

## 第四遍：细节打磨

- [ ] 句长和段落长短有变化，手机端阅读顺畅；不按固定字数强行切句
- [ ] 一段主要承载一个意思，连续步骤可用列表，推理连贯时允许保留稍长段落
- [ ] 朗读顺畅：大声朗读无拗口，停顿自然
- [ ] 标点自然：多用句号，少用逗号连长句；感叹号适度
- [ ] 标题层级清晰，重点内容突出；表格只在适合时使用
- [ ] 审校报告在对话窗口展示，**禁止**写入最终 .md 稿件文件

## 二次扫描（只扫本轮改动）

- [ ] 本轮改动没有新增假深刻结构
- [ ] 本轮改动没有新增意义拔高和万能展望
- [ ] 本轮改动没有新增金句、排比、漂亮比喻
- [ ] 本轮改动没有新增未经核验的数据、场景、例子
- [ ] 本轮改动没有删掉作者有辨识度的语气和手迹
- [ ] 输出了关键改动说明表：原文 / 修改 / 原因 / 可还原
- [ ] **本轮改动没有把 R4 的免责句挪远**：为精简而删除或后移「阈值是自设的 / 未校准 / 虚构」等披露，视为新增缺陷
- [ ] **本轮改动没有删掉样本量、口径、费用、延迟等限制性数字**：只留结论不留边界的改法一律回退

## 图卡模式审校（card_post 模式输出时额外执行）

### 字数与数量

- [ ] 图卡内容排版（封面 + 内容卡正文）总字数不超过 1000 字
- [ ] 卡片总数不超过 9 张（含封面）
- [ ] 每张内容卡只有一个核心主题，标题具体（无空泛口号）
- [ ] 每张内容卡要点数量为 3-4 条

### 事实准确性

- [ ] 所有版本号、发布时间、性能数据、功能名有官方来源
- [ ] `excluded_claims[]` 中的事实未出现在发布内容（【发布配文】和【图卡内容排版】）
- [ ] 未使用「100%」「史诗级」「全网最强」「首个」「唯一」「完全免费」「无限」等绝对化表述
- [ ] 语言有冲击力，但未牺牲事实准确性

### 内容质量

- [ ] 卡片之间没有重复观点
- [ ] 封面包含强钩子标题 + 具体利益点
- [ ] 要点每条不超过 24 个汉字

### 输出格式

- [ ] 输出包含【事实核查摘要】
- [ ] 输出包含【卡片数量决策】
- [ ] 输出包含【发布配文】
- [ ] 输出包含【图卡内容排版】
- [ ] Card 编号连续（Card 01、Card 02…）
- [ ] 输出已落盘到 `{workspace}/output/{YYYYMMDD}-card-{slug}.txt`
